`app_universal.py` universal-map prototype), `backend/`, `lastfm/`, `spotify/`, `data/`,

Every bug below with a test has a **strict xfail** carrying its ID. When you fix the bug,

the test becomes a regression guard. `grep -rn "BUG-07" tests/` finds the test for any ID.

## 1. Summary

The Coachella map is in decent shape. Rendering, filtering, discovery mode, the playlist and
mobile drawer all work in a real browser, and the frontend escapes untrusted strings correctly.
The problems sit mostly at the edges:

1. **Auth is unsafe for more than one user.** spotipy's default `.cache` file means the second
   person to log in gets the first person's Spotify account (BUG-01, confirmed in both apps).
2. **Personalization is mostly dead.** `graph_static.json` has no `similar_artists`, so
   "derived" scoring never fires (BUG-04). Only exact lineup matches light up.
3. **The universal map is a prototype that doesn't yet do its job.** It builds 5 nodes, can't
   expand from the UI, forgets the map on reload, swallows pipeline errors, has an exploitable
   XSS, and serves Deezer previews that expire 15 minutes after they're cached.
4. **Repo hygiene.** API keys sit in a tracked doc in a public repo (already rotated), personal
   listening data is committed, the legacy "tests" delete the real cache, and 8 overlapping
   markdown docs contradict the code.

**Do these first** (about a day of work, all low risk):
BUG-01 → BUG-20 → BUG-21 → BUG-04 → BUG-37/36/08 → BUG-19.

Isolation guarantees (`tests/conftest.py`):

* All HTTP through `requests`/spotipy is intercepted by `responses`. An unmocked call raises.

* A session guard fails the run if any file under the real `data/cache` or `data/users` changes.
* Browser tests run offline: d3 is vendored in `tests/e2e/vendor/`, and fonts and third-party
  hosts are aborted. Audio comes from a local silent-WAV server.

## 5. UI testing notes (observed in Chrome 1440×900 and a 390×844 touch device)

* First load + settle ≈ 5.8 s locally. 790 ms of that is one blocking long task (PERF-01).
* Dragging the edge-threshold slider across its 6 stops costs 6 × ~770 ms of jank.
* The controls panel overlaps graph nodes in the bottom-left on desktop. On mobile it opens
  expanded over the top half of the screen.
* No keyboard access: nodes aren't focusable and there are no ARIA labels. The graph is
  mouse/touch only. Worth an accessibility pass if this ever ships publicly.
* Detection of the mobile layout uses `'ontouchstart' in window`, so touchscreen laptops get the
  mobile drawer UI.
* The playlist lives only in memory: reloading or logging in/out loses it. Duplicates can be
  added. Consider `localStorage`.
